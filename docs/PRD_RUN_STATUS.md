### 本轮需求拆解（4 项明确诉求）

1. **局内角色状态面板**：战斗中可查看当前角色状态，含装备与技能宝石。
2. **技能详细说明**：每个技能有可读的说明文字与等级效果。
3. **详细数值**：展示当前真实生效数值，最好能看到来源分解。
4. **UI 不合理处一并修复**：梳理并修复现存 UI 问题。

## 2. 产品目标

1. **局内信息透明**：玩家在战斗中随时能看到「我是谁、穿了什么、镶了什么、会什么技能」，不再依赖结算或局外面板推断。
2. **数值可信**：面板展示的是引擎真实生效的数值（读 `StatBlock`），而非局外面板的估算口径；每个关键数值可追溯到来源。
3. **交互一致**：技能说明、装备描述、数值口径在局内/局外/弹窗三处统一，消除文案漂移与重复实现。
4. **阅读不被打断**：升级弹窗与状态面板的阅读行为不会被战斗推进"背后打死"，暂停语义清晰且可控。
5. **修复明确缺陷**：一并处理勘察中确认的 UI bug（HUD 玩家选取、reset 闪帧、空槽缺失等），降低认知噪音。

## 3. 用户故事

1. 作为**割草局内的玩家**，我想随时打开一个角色状态面板查看总览（身份/等级/生命/核心属性），以便在不离开战斗上下文的情况下确认自己当前状态。
2. 作为**在局内堆积装备的玩家**，我想查看 13 个装备槽当前穿了什么、每件的词缀与已镶嵌宝石，以便理解"我为什么变强/变弱"并决定后续拾取取向。
3. 作为**升级三选一的玩家**，我想看到每个技能的详细说明文字和"等级 +1 后具体变强多少"，以便做出有意义的取舍，而不是靠猜。
4. 作为**在意数值的硬核玩家**，我想看到攻击/暴击/护甲等详细数值及其来源分解（基础值、词缀、宝石、套装、传奇各贡献多少），以便验证配装收益是否真实生效。
5. 作为**正在阅读升级卡片的玩家**，我想在弹窗显示期间战斗暂停，以便从容比较选项而不被敌人偷袭致死。
6. 作为**多席位/影子玩家场景的玩家**，我希望 HUD 与状态面板始终显示"我"的角色数据而非固定第一个实体，以便联机或带影子时信息不错位。
7. 作为**开局的玩家**，我希望 HUD 在首帧就显示正确的初始数值而不出现 `120/120` 到真实值、`100` 分到真实分的闪烁，以便获得稳定的第一印象。
8. 作为**维护者/后续开发者**，我希望技能描述与数值口径有单一事实来源，以便局内面板、局外面板、升级弹窗不再各写一套而互相漂移。

## 5. 局内面板信息架构建议（供架构师参考，不强制）

### 5.1 形态建议：Tab 式四页

```
┌──────────────────────────────────────────┐
│  角色状态            [角色][装备][技能][数值]  [×] │
├──────────────────────────────────────────┤
│                                          │
│   角色页：身份/等级/经验/生命/核心属性速览      │
│   装备页：13 槽网格 + 词缀 + 镶嵌宝石（空槽占位）│
│   技能页：3 技能槽卡片 + 详细说明 + 等级增益    │
│   数值页：属性列表 + 来源分解 +（可选）公式链    │
│                                          │
└──────────────────────────────────────────┘
```

- 备选：单页分区滚动（若 Tab 切换成本过高）。两种均可，以"信息可一次看全、不遮挡 HUD"为准。
- 数据链路：`ECS(StatBlock / PlayerLoot) --presentation 读取--> 只读 VM --> 面板渲染`。面板模块零 ECS 写入（FC-5.3）。

### 5.2 打开/关闭入口

- 打开：HUD 固定按钮 + 键盘 `Tab`（与既有键位冲突时以架构评估为准）。
- 关闭：`Esc` / 关闭按钮 / 再次按 `Tab`。
- 与升级弹窗互斥：升级弹窗弹出时面板自动收起或置灰，避免两个浮层叠加。

### 5.3 战斗中是否暂停（关键决策点）

| 场景 | 建议 | 说明 |
| --- | --- | --- |
| 升级三选一弹窗 | **必须暂停**（RS-05，P0） | 用户明确诉求"阅读时不被打死"；当前为明确 bug。 |
| 角色状态面板（手动打开） | **建议暂停**，但列为待确认（见 §7-Q2） | 暂停会改变 tick 推进，需评估对确定性回放/快照的影响。若暂停代价过高，可退化为"面板打开时短暂无敌/减伤"或"非暂停但战斗弱化的观战态"。 |

## 7. 待确认问题（需用户 / 架构师拍板）

| ID | 问题 | 背景与选项 | 建议 |
| --- | --- | --- | --- |

| Q4 | **数值来源分解的粒度与属性范围**？ | `StatBreakdown` 含 `final/buckets/bySource`；是否所有属性都展示分解，还是仅核心属性？是否需要展示乘区 bucket？ | 建议 P0 先覆盖 攻击/生命/暴击/护甲 的 `bySource`，`buckets` 公式链放 P1（RS-08）。 |
| Q5 | **`getEquipped()` 补全空槽是否影响现有调用方**？ | 当前返回结构不含空槽；补全为 `null` 后，若有调用方遍历键可能多出 `null` 值。 | 需架构快速核对调用点，确认无遍历假设被破坏；本轮按"补全"执行（RS-02/RS-06）。 |
| Q6 | **面板键盘入口是否与既有键位冲突**？ | 建议 `Tab` 打开、`Esc` 关闭；需确认未与操作/主题/触屏键位冲突。 | 由架构结合 `InputSystem` 键位表定；冲突则改用 HUD 按钮为主、`Tab` 为辅。 |

## 9. 交付给架构师的要点摘要

1. 新 UI（局内状态面板）**必须经 presentation 层读 ECS 注入只读 VM**，不得直连 ECS（FC-5.3）。
2. 面板数值口径**必须是 `StatBlock` 真值**，不得复用局外 `statsOf()` 中值口径。
3. 需新增/补全的只读接口：`getEquipped` 空槽补全、背包只读访问器、`StatBreakdown` 实现。
4. 技能说明需要**单一事实来源**，同时服务面板与升级弹窗。
5. **升级弹窗暂停为 P0**，但暂停对确定性基线的影响需在 Q2/Q3 拍板后落地。
6. 需求池 P0 共 6 条（RS-01~RS-06），P1 共 3 条（RS-07~RS-09），P2 共 3 条（RS-10~RS-12）。
